# ZnanyLekarz

> ZnanyLekarz (znanylekarz.pl) is the Polish healthcare marketplace and practice-management
> platform operated by Docplanner Group, listing over 146,000 doctors and giving medical practices
> online booking, calendars, reminders, reviews, e-prescriptions, video consultations and payments.
> Its public developer surface is the Docplanner Integrations API — an OAuth 2.0 REST API served on
> the www.znanylekarz.pl host that lets medical-software vendors synchronise facilities, doctors,
> addresses, services, insurance providers, calendars, breaks, slots and bookings, and receive
> push or pull notifications when patients book, move, confirm or cancel visits.

## What an agent needs to know first

- Base URL (Poland): https://www.znanylekarz.pl/api/v3/integration
  The published OpenAPI server is templated — https://www.{domain}/api/v3/integration — because one
  contract serves thirteen Docplanner marketplaces. The specification's own locale table maps
  Poland to znanylekarz.pl. HTTPS is mandatory on every request.
- Auth: OAuth 2.0 client_credentials, scope `integration`, tokens valid 3600 seconds.
  Token endpoint: https://www.znanylekarz.pl/oauth/v2/token (note: SSO is v2 while the API is v3).
- ACCESS IS GATED. The documentation is fully public; the credentials are not. The API is
  "exclusively available to medical software providers" and credentials are issued only after a
  sandbox request, a kick-off meeting, acceptance testing and production approval. An unauthenticated
  call returns 401 {"message":"Authentication credentials could not be found."}
- THIS IS A LIVE CLINICAL SCHEDULING SURFACE. Writes create, move and cancel real patient
  appointments. There is NO idempotency mechanism and NO dry-run mode. A blind retry of bookSlot,
  moveBooking or replaceSlots can duplicate or destroy a real appointment.

## Runtime semantics

- Pagination is OPT-IN: `page` and `limit` (default 100). Omit `page` and the collection comes back
  unpaginated. Responses are `{"_items": [...]}` with no total, no cursor and no Link header.
- Field expansion uses `with` — closed enums per operation, e.g. `facility.doctors`,
  `doctor.addresses`, `booking.patient`, `slot.services`. These widen the payload; they do not
  grant permission.
- Errors: application/vnd.error+docplanner+json carrying {"errors": [], "message": "..."}.
  Not RFC 9457. No machine-readable error code.
- Rate limits: X-RateLimit-Limit / -Reset / -Used / -Remaining, 429 on exhaustion. The numeric
  ceilings are per-client and not published. Missing headers mean limiting is disabled.
  POST /notifications/release is hard-limited to 1 request per hour with Retry-After.
- getSlots accepts a maximum date range of 180 days; wider returns 400.

## Events

17 typed callbacks, delivered by push (retried after 5 and 10 minutes, replayable via
POST /notifications/release for 14 days) or pulled FIFO from /notifications (expiring after 72
hours). Two are BLOCKING — `slot-booking` and `booking-moving` — where a non-2xx from your endpoint
denies the patient's booking or move. Source IPs are published as machine-readable JSON at
https://www.znanylekarz.pl/public/docs/public-ips.json
